# Endless Nightlord Gauntlet - a DoubleBOSS (Nexus #952) variant

Built on top of **DoubleBOSS** by the original author. Same delivery format (a `mod/`
folder loaded by a **me3** profile with Seamless Co-op), same assets - only the event
scripts are changed.

**What DoubleBOSS does:** after you kill the expedition's Nightlord it does not roll the
results screen. It warps the team back into the arena and spawns a second, random
Nightlord for one more fight; killing that one ends the run.

**What this variant does:**

| | DoubleBOSS | This mod |
|---|---|---|
| Chained Nightlord fights | exactly 1 | **unlimited**, until the run actually ends (team wipe / abort) |
| After each chained kill | results screen | next Nightlord spawns, kill is counted |
| Consumables | none | **replenished every 3 chained kills** (`REFILL_EVERY`, see below) |
| Which Nightlord | random once per expedition | **a fresh random Nightlord every round** |
| Difficulty ramp | - | none; every round is a fresh full-HP boss |

---

## 1. Compile the scripts first (required)

The compiled `*.emevd.dcx` files for the four map scripts are **not** included: the endless
logic lives in the `.emevd.dcx.js` sources and must be compiled before the game can load it.
(The original mod ships its `.js` files for the same reason - that is the authoring format.)

1. Install [DarkScript3](https://github.com/AinTunez/DarkScript3/releases) (a release with
   Nightreign support). No extra EMEDF file is needed - every `.js` header says
   `@docs nr-common.emedf.json`.
2. Open each of these in DarkScript3 and press **Ctrl+S** (File > Save). It compiles the
   script and writes `<name>.emevd.dcx` next to the `.js`:
   - `mod/event/m16_00_00_00.emevd.dcx.js`
   - `mod/event/m16_10_00_00.emevd.dcx.js`
   - `mod/event/m18_00_00_00.emevd.dcx.js`
   - `mod/event/m19_00_00_00.emevd.dcx.js`

   Keep `common_func.emevd.dcx` in the same folder - the scripts are `@linked` to it and
   will not compile without it.
3. DarkScript3 reports compile errors in its error window. All four `.dcx` files are needed.

## 2. Install

1. Copy the whole `EndlessNightreign` folder anywhere.
2. Put **Seamless Co-op for Nightreign** in `EndlessNightreign/SeamlessCoop/` so that
   `nrsc.dll` sits at `EndlessNightreign/SeamlessCoop/nrsc.dll` (exactly what the original
   DoubleBOSS profile expects).
3. Launch through **me3** and pick `EndlessNightreign.me3`.

`savefile = "NR0000.co2"` and `start_online = false` are unchanged from the original.
`mod/map`, `mod/msg`, `mod/regulation.bin` and `common_func.emevd.dcx` are the original
files, untouched - this is purely an event-script mod.

## 3. Configuration

Everything is generated by `tools/endless_transform.py`; change the two constants at the top
and rerun it from the folder containing `DoubleBOSS/` to regenerate the `EndlessNightreign/`
sources (then recompile, step 1):

```python
REFILL_EVERY = 3        # 0 = no refill at all
REFILL_SPEFFECT = 509   # spEffect applied to each player on a refill
```

`509` is the restore the game itself applies on a boss kill. If your consumables are not
restocked by it, swap in the spEffect (or flag/item instruction) that does - the block is
repeated verbatim in each of the four scripts under
`// 3 bosses defeated: replenish consumables`, so it can also be hand-edited.
Counter flags: `19300101`/`19300102` (kills since last refill), `19300002` (first round
played); all cleared in `19110900` on run start.

## 4. What was changed in the event scripts

Flags kept from the original: `7512` = expedition finished (results), `19002951` = start
chained fight, `19002952` = team warped / boss may spawn, `19002953` = chained fight live,
`19002954` = map boss defeated latch, `19002955` = boss spawning, `19002956/57` = chain armed.

Per map script (`m16_00`, `m16_10`, `m18_00`, `m19_00`):

1. **`19002951` (round manager)** - the one-shot "warp the team into the arena" transition is
   now a loop: clear `19002952/53/55`, show the "next Nightlord" interlude, warp everybody,
   set `19002952`; wait until the death handler clears `19002952`; repeat. The first interlude
   keeps the original 8 s + 3 s + text `6015`, later ones are 4 s.
2. **`19114900`-`19114905` (per-Nightlord spawn)** - each spawn event loops instead of ending:
   wait for `19002952`, re-`EnableCharacter` the boss (the death handler disabled the corpse),
   play the original entrance sequence, set `19002953`, then wait for the round to finish.
3. **`19309000` (new; replaces the stock death handler for the chained boss)** - the same
   defeat feedback the game gives (`IncrementTeamBossesKilled`, SE, `RecordUserDispLog`, BGM
   stop, health bar hidden, heal `509`, victory text) but it **never sets `7512`**, so the
   results screen does not trigger. It counts the kill, runs the refill block every N kills,
   and disables the corpse for the next round. Registered instead of common_func `90075901`
   for 圣牢布 / 米塔恩 / 王三狼 / 王人马 / 王冰龙, and instead of `190075904` for 垃圾王.
4. **`190017580`** (extra 圣牢布 death handler that ended the run) - no longer initialized.
5. **`19110900`** - arms **all six** Nightlord families (the original arms only the one
   `RandomAppearLot` rolled, which is why DoubleBOSS always repeats that one) and clears the
   round-pick flags on run start.
6. **Per-round lottery** - at the start of every round the host sets one random flag out of
   `19300010`-`19300015` with `RandomlySetNetworkconnectedEventFlagInRange`; the round manager
   resolves the result into exactly one of `19300020`-`19300025` (lowest index wins if the
   game ever sets more than one), and only that family's spawn event and death handler react
   to the round. The flags are network-connected, so all co-op peers see the same pick.

## 5. Known risks (please read before reporting a bug)

This was written by reading the mod's decompiled scripts, **not** by playing it - I could not
run Nightreign or compile the EMEVD in my environment. Check these first, in order:

1. **Boss revival.** Round 2+ depends on `DisableCharacter` + `EnableCharacter` respawning the
   Nightlord at full HP (that is what the mod's own entrance events do). If a boss comes back
   already dead, invisible, or at 1 HP, this is the thing to fix.
2. **垃圾王 (two-phase boss).** Its phase transition and the endless loop both drive
   `19002953`; the loop clears that flag on death, which could cut a phase-2 transition short.
3. **BGM / health bar leftovers** between rounds for 米塔恩 and 王冰龙, whose entrance events
   were written to run once.
4. `IncrementTeamBossesKilled(1)` now fires every round; if the kill counter is capped or
   feeds the rewards screen, the run may still end after some number of kills.
5. Interlude timing: 4 s between later rounds may be too short while the team loots - raise
   the `WaitFixedTimeSeconds(4)` in the round manager.
6. **Round lottery.** If a round starts and no Nightlord shows up (the fight flag `19002953`
   never comes on), the roll/selection path is the suspect: inspect `19300010`-`19300015`
   (raw roll) and `19300020`-`19300025` (resolved pick) in a flag debugger. The roll is done
   by the host only; if a client thinks it is the host and rolls independently, two families
   can be armed - the manager resolves that to one, but the pick may then disagree between
   peers. `RandomlySetNetworkconnectedEventFlagInRange` is a stock instruction the game itself
   uses, but it is called from a map event here.
7. All six families' init events now run at run start, so all their per-family common-event
   registrations (BGM heat-up, health-bar links, buffs) are live at once. That is what makes
   rotation possible and is the part I would watch most closely in the first real session.

## 6. Rollback

The original `DoubleBOSS/` folder sits next to this one and its compiled `.dcx` files are the
untouched two-boss version, so launching `DoubleBOSS.me3` restores the original mod.
